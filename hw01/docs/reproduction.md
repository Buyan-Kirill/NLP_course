# Воспроизведение

Команды выполняются из `hw01/`. Для демонстрации достаточно установки
зависимостей и ноутбука; подготовка корпуса и обучение — отдельный маршрут.

## Установка и ноутбук

Нужен **Python 3.12**. Используйте собственное окружение и его же ядро в VS Code
или Jupyter. Фиксированного имени или расположения окружения нет.

| Система | Установка в выбранный Python |
|---|---|
| Windows x86-64, NVIDIA | `py -3.12 -m pip install -r requirements.txt` |
| Linux/WSL x86-64, NVIDIA | `python3.12 -m pip install -r requirements.txt` |
| Windows/Linux без NVIDIA | тот же интерпретатор, `-m pip install -r requirements-cpu.txt` |
| macOS Apple Silicon | `python3.12 -m pip install -r requirements.txt`; выполнение на CPU |

Если системный `pip` падает с `No module named distutils`, ошибка возникает
до чтения requirements. Используйте Python 3.12 с исправным pip, при необходимости
создав своё окружение через `python3.12 -m venv <папка>`; не запускайте старый
системный pip через другой Python. В Windows аналогичная команда начинается с
`py -3.12`. В Linux модуль `venv` может требовать отдельного пакета дистрибутива.

Откройте [inference.ipynb](../inference.ipynb) и выполните **Run All**.
Код `continue_poem` импортируется из [scripts/try_poetry.py](../scripts/try_poetry.py).
Первая ячейка скачивает примерно 415 МБ ресурсов один раз и проверяет SHA256
архива и каждого файла. Последующие запуски используют локальные файлы.
Ячейка диагностики показывает интерпретатор, сборку PyTorch и выбранное устройство.

Для NVIDIA нужен совместимый драйвер, отдельный CUDA Toolkit не требуется.
CPU поддержан, но одна строка может занимать несколько минут. Windows CUDA
и Linux CPU/WSL проверены; Linux CUDA отдельно не проверялся. Для macOS ARM64
проверена доступность прямых wheel-зависимостей, полноценный запуск на Mac
не проверялся. MPS и macOS Intel в этом комплекте не поддержаны.

## Данные → массивы

```bash
python -m reproduction.datasets download
python -m reproduction.datasets build
python -m reproduction.datasets prepare
```

1. Загрузка получает исходные XML/CSV/HTML из публичных источников. Каталог,
   revisions и SHA256 находятся в `reproduction/corpus/manifest.json`.
   Проверенные файлы кешируются; повтор команды не скачивает их заново.
   Полная загрузка — около 1,12 ГБ, 3015 файлов; скорость зависит от библиотек.
2. Сборка восстанавливает отобранные произведения и фрагменты по зафиксированным
   границам и адресным правкам. Каждый текст, итоговый JSONL и метаданные
   проверяются по исходному хешу. Решения отбора и split воспроизводятся из
   рецепта; текущий сайт не используется для нового автоматического отбора.
3. Подготовка кодирует произведения целиком, добавляет EOS, восстанавливает
   смещения документов, поэтические окна и примеры с подсказкой окончания.
   SHA массивов и индексов должны совпасть с выбранным экспериментом.

Исходники Lib.ru и РВБ не закреплены git revision. Для Lib.ru допускается
изменение служебного HTML только при совпадении SHA всех зафиксированных
извлечённых представлений тела страницы. Ожидаемый и полученный SHA HTML
записываются отдельно. Изменение самого тела или недоступный источник вызывают
ошибку; другой текст вместо него не подставляется. Список проблем сохраняется
в `.cache/source_failures.json`.
Ранее полученный исходный файл можно положить в соответствующий кеш только
при совпадении SHA. Полные тексты в Git не распространяются.

Поставляемый BPE обучен с нуля на данных проекта и зафиксирован в
`artifacts/tokenizers_v3/selected/tokenizer.json`. Он нужен для совместимости
токенов с готовыми весами. Код обучения другого BPE — `reproduction/fit_tokenizer.py`;
это отдельный эксперимент, его token IDs нельзя подставлять в готовые веса.

## Обучение

```bash
python -m reproduction.run list
python -m reproduction.run stage pretrain --execute
python -m reproduction.run stage pretrain_finish --execute
python -m reproduction.run stage poetry --execute
python -m reproduction.run stage poetry_small_batch --execute
python -m reproduction.run stage ending_plan --execute
python -m reproduction.export
```

Без `--execute` команда только показывает конфиг и запуск. Обучение последовательно,
по одной модели на GPU. Основной рецепт рассчитан на NVIDIA GPU с BF16 и примерно
16 ГБ памяти; CPU используется для коротких проверок работоспособности.
Претрейн начинает с `GPT(ModelConfig(...))` и случайных весов. Все последующие
этапы получают checkpoint предыдущего этапа, не поставляемые готовые веса.

Каждый этап сохраняет `last.pt`, `best.pt`, конфиг, окружение, `metrics.jsonl`
и `status.json` в `runs/reproduction/<этап>/`. Для продолжения той же команды
добавьте `--resume`. Восстанавливаются оптимизаторы, RNG, порядок данных
и накопление токенов; изменённые конфиги или входы отклоняются.
Переход к следующему этапу разрешён только после завершения бюджета предыдущего.
Воспроизведение сохраняет формулы и бюджеты; новые SHA checkpoint ожидаемы.
Технический лимит длительности этапа увеличен до семи суток, чтобы не переносить
ограничения исследовательских запусков на другое оборудование.

Экспорт записывает локальные веса и конфиг в `artifacts/local/`. В ноутбуке можно
передать `config='artifacts/local/system_config.json'` в `continue_poem`, чтобы
проверять собственный результат. Обычный вызов использует поставляемые веса.

## Проверки и отчёт

```bash
python -m unittest discover -s tests
python -m reproduction.build_report
```

Тесты используют маленькие фикстуры, проверяют причинную маску, сдвиг labels,
покрытие токенов, Muon/AdamW, восстановление обучения, границы данных и инференса.
Они не запускают полное обучение. HTML собирается из сохранённых измерений
и исходных генераций; происхождение чисел и текстов указано в отчёте.
